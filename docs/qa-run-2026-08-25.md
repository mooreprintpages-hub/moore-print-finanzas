## Validaciones aprobadas

### RLS estructural

Todas las tablas públicas inspeccionadas tienen RLS activado y al menos una policy. No se detectaron tablas públicas del modelo operativo con RLS deshabilitado.

### Propietario

La membresía activa está ligada al rol `Propietario` y el rol tiene 33 permisos permitidos.

Simulando la sesión Auth del propietario bajo el rol PostgreSQL `authenticated`:

- Puede ver el negocio.
- Puede crear un área ligada a la sucursal existente.
- La escritura de prueba fue revertida con `ROLLBACK` y no dejó datos permanentes.

### Usuario externo / sin membresía

Simulando un UUID sin membresía bajo el rol PostgreSQL `authenticated`:

- Ve 0 negocios.
- Ve 0 clientes.
- Intentar insertar un área para Moore Print falla con `new row violates row-level security policy for table "areas"`.

## Seguridad

Supabase Security Advisor sólo reportó una advertencia en esta corrida: `Leaked Password Protection Disabled`. No es una falla de RLS; corresponde a una opción de seguridad de Supabase Auth que conviene activar antes de producción definitiva.
